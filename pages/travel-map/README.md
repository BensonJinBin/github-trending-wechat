# 点亮我的旅行地图

点亮去过的中国省份（可细到城市），实时算出国土和人口覆盖率，标记想去的地方，
转发给好友对比足迹，一键生成分享图。

移植自 `creation/china-travel-map`（网页版），但代码完全独立，不依赖那边任何文件。

## 怎么打开

**这一页是小程序的启动页** —— `app.json` 的 `pages` 数组第一项就是它，打开小程序直接进这里。

原来的 GitHub Trending 页（`pages/index/index`）还在，但**已经没有入口了**：既没进 tabBar，
本页也没加跳转。要进去只能用条件编译（开发者工具左上角编译模式下拉），
或者自己加一个 `navigateTo({ url: '/pages/index/index' })`。

`project.config.json` 里留了一个「旅行地图」的编译模式，克隆下来就有；
现在它和默认编译是同一个页面，留着是为了改启动页时不用重配。

## 小程序码

分享长图底部会画一枚小程序码 —— 图片能传播但点不了，得给看到图的人一个入口，
微信里长按图片就能「识别图中小程序码」。

`mpcode.png` 已经放好了（448×448，从公众平台后台下的码转的）。要换码就覆盖这个文件，
**转成 PNG 别直接用 JPEG** —— 码点是硬边缘，JPEG 的振铃会糊边，直接影响识别率。

**文件不在也能跑**：出图时底部会自动退化成居中的「你去过几个省？/ 点亮你自己的旅行地图」
两行字，不留空框、不报错。

### 必须留意：这个文件会被打包器误删

`project.config.json` 里开着 `ignoreUploadUnusedFiles`，它靠静态分析判断文件有没有被引用。
`mpcode.png` 只在 JS 里以字符串常量出现（`CODE_PATH`），分析器认不出来，
**上传时会被当成无用文件剔掉** —— 开发者工具里一切正常，线上码消失。

所以它被显式写进了 `packOptions.include`。换文件名的话记得同步改那里。

### 白卡的形状和亮度

纯白压在纯黑上是整张图对比度最高的东西，比点亮的省份还亮 —— 扎眼的是**白**，不是大
（按面积它只占 2.4%）。所以压存在感走的是这两个旋钮，`poster.js` 的 `CARD`：

| 字段 | 现值 | 作用 |
| --- | --- | --- |
| `shape` | `'circle'` | 圆卡。码本身是圆的，圆卡白面积比方卡少 21%（πr² vs 边长²） |
| `dim` | `0.06` | 再压 6% 亮度。白和绿一起变暗，**对比比值不变**，只损失很小的绝对差 |
| `pad` | `8` | 图在卡里的内缩，见下 |

**圆卡不损失识别率**：码环是圆的，要的静区是径向的，圆裁掉的只是四角那些没用的白，
裁完径向白边仍是均匀 12px，和方卡时一样。`dim` 别超过 0.1，再往上就开始发灰发脏。

### 尺寸余量（实测数字，不是估的）

| | |
| --- | --- |
| 源图码环 | 占 448px 的 96%，自带静区只有 2% |
| 卡片 222 逻辑px，内缩 8px | 码环实际 198 逻辑px |
| 导出 2 倍 | 395 设备px |
| 朋友圈压缩后（长边压到 1080） | 约 111 px |

内缩那 8px 不能省。源图几乎没有静区，码环外那 12.5px 白边是识别要用的；
去掉能让码大 7.5%，但静区从 6.3% 掉到 2.1%，不划算。

**导出倍率对这个数字没有影响** —— 决定压缩后码有多大的是「码占整图宽度的比例」（222/1080 ≈ 20.6%），
不是导出了多少像素。所以调 `EXPORT_SCALE` 救不了识别率。

真机测过再定。如果朋友圈压缩后扫不出来，能动的只有这几处，按代价从小到大：

1. `poster.js` 里 `drawCodeCard` 的 `pad` 从 8 改到 0，加 `ctx.clip()` 保住圆角（+7.5%）
2. 去掉底部日期，把卡片放大到 250 左右（+13%）
3. 长图改成 4:5（1080×1350）。朋友圈压长边，4:5 压完宽度是 864 而不是 608，
   码能到 178px —— 但整个版式要重排

## 移植时改掉的地方

网页版那套在小程序里跑不了，这几处是重写的：

- **`Path2D` 没有** —— 数据里的 `d` 只含 M/L/Z，是纯折线，所以 `geo.js` 自己解析成
  多边形环。拆完顺带解决了命中判断：不用 `ctx.isPointInPath`（各端实现不一致），
  直接射线法算，还能在不画图的情况下判断。
- **SVG 地图 → canvas** —— 网页版靠 SVG 元素接点击事件，这里整张图画在一个 canvas 上，
  `bindtouchstart/end` 拿相对 canvas 的坐标反推 viewBox 坐标再命中。滑动超过 10px
  当成滚页面，不算点选。
- **`ctx.letterSpacing` 没有** —— 长图标题的字距只能逐字画（`poster.fillTracked`）。
- **导航栏自绘** —— 默认导航栏的标题和页面里的大标题重复了，所以 `navigationStyle: "custom"`
  整个去掉，和网页版一样做成通栏深色。代价是要自己处理两件事：内容的 padding-top 按
  `wx.getMenuButtonBoundingClientRect()` 算，压到右上角胶囊下面（居中的大标题在 375pt 屏上
  宽约 240px，不让位会被胶囊压住）；返回键微信也不给了，自绘一个，
  只在 `getCurrentPages().length > 1` 时显示 —— 现在这页没入口、直接启动时不该有返回键，
  以后从首页跳过来才需要。
- **`localStorage` → `wx.storage`** —— 直接存 id 数组，走项目现成的 `utils/storage.js`。
  网页版把 34 个省压成 5 字节 base64url 是为了塞进 URL 分享，小程序没这个需求。
- **canvas 的 font 只写 `sans-serif`** —— 小程序解析带空格的中文字体名（`"PingFang SC"`）
  不稳，会静默 fallback。而 iOS 的 sans-serif 就是苹方、Android 就是思源黑，正好是想要的。

绘制逻辑（`paint.js` / `poster.js`）是纯 canvas 2D 代码，改完可以丢进浏览器跑一遍验证，
不用每次都开模拟器。

## 配色随点亮数变

`themes.js` 定义 5 档配色，跟着点亮省份数自动切，用户不用选也没法选。

| 档 | 省份数 | 覆盖人群 | 主色 |
| --- | --- | --- | --- |
| t1 靛蓝 | 0–4 | 垫底 32% | `#2B6BFF` |
| t2 青 | 5–12 | 32%→76%，大多数人在这 | `#00C4B4` |
| t3 琥珀 | 13–21 | 76%→95% | `#FFB020` |
| t4 珊瑚 | 22–33 | 95%→99.8% | `#FF5A4E` |
| t5 满贯 | 34 | 全部 | `#A855F7` |

几个定这些数的理由：

- **颜色本身就是「去过多少地方」的可视化**，不是用户偏好。所以它不稀释品牌识别 ——
  版式、字体、地图全不变，只有色相在动，朋友圈里刷到还是认得出，但一眼能看出深浅。
- **档位按 `poster.PCT` 曲线切**，让分布落在对的地方。第一次变色在第 5 个省，来得够快，
  新用户点几下就能撞到，不至于玩半天没反应。
- **不加任何文字说明。**「青铜白银」那种标签一加就俗了，颜色变了用户自己会发现。
  而且「超过全国 X% 的人」那行已经在表达同一件事，颜色只是强化它。
- **避开绿色** —— 小程序码是绿的，撞色。

### 两侧怎么同步

canvas 的颜色在 JS、页面的颜色在 wxss，没法共用一份，**只能靠 `t1`…`t5` 这个 key 对齐**：

- **canvas**（屏幕地图 + 导出长图）：`paint.applyTheme(t)` 改模块级的 `paint.C` 和
  `LAND_GLOW.color`。屏幕和长图读的是同一份，所以一改两边一起变 —— 这是有意的，
  不能出现「屏幕是蓝的、导出是金的」。
- **页面**：根节点 `<view class="root {{tier}}">` 挂主题类，wxss 里 `.root.t2` 之类
  重定义 CSS 变量往下级联。只有带主色的地方跟着变（数字、胶囊选中态、主按钮、中性文字）；
  面板底和胶囊未选中态是 `#0B0F1A` 那种近黑色，那个深度下的蓝味看不出来，五档共用一套。

**改 `themes.js` 记得同步改 wxss 里的 `.root.tN`**，反之亦然。这份重复没法消除。

调用时机：`applyTier()` 必须在 `drawMap()` **之前** —— `paint.C` 是模块级的，
画之前定不下来就画错色。

## 明暗调子

真机上第一版偏暗淡，根因不是背景色，是**只有两个明度层级**：纯黑背景和 `#0A1330` 的未点亮
陆地，差得太小，陆地浮不起来；点亮的省份又直接跳到 `#2B6BFF`，中间是断的。
只点亮两三个省时，整张图 90% 是死黑。

调子集中在三个常量，改这里就够：

| 位置 | 常量 | 现值 | 作用 |
| --- | --- | --- | --- |
| `paint.js` | `C.dim` / `C.dimLine` | `#12204A` / `#2C4079` | 未点亮陆地。**最关键的一个**，让陆地成为可读的形状 |
| `poster.js` | `AMBIENT` | `r900 alpha .46` | 环境光，一团居中的蓝雾。铺太小顶部标题和底部码会悬在死黑里 |
| `paint.js` | `LAND_GLOW.steps` | `[]`（关） | 整块陆地的外发光，想更亮就打开 |

`LAND_GLOW` 默认**开着**。它本来是关的 —— `dim` 提亮之后陆地已经和背景分得开，
再叠一层会压掉点亮省份的对比。后来发现真机上那圈陆地光是 `shadowBlur` 泄漏漏出来的
（见下面「几个坑」），修掉之后观感会突变，所以把它做成可控的并打开，
保住原来的样子。想去掉把 `steps` 置成 `[]`。

`C.dim` 同时作用于屏幕地图和导出长图（两边共用 `paint.drawMap`），所以改一处两边一起变，
不会出现"屏幕上好看、导出来不一样"。

## 几个坑

- **微信的 canvas 里 `shadowBlur = 0` 关不掉阴影。** 这是踩得最狠的一个。
  `poster.js` 的 `row()` 给「点亮 N 个省」那个数字加了发光，用完只写了 `shadowBlur = 0`
  —— 浏览器认，微信不认，之前设的 `shadowColor` 一直挂着，**后面画的每一样东西都带上那圈蓝光**：
  陆地、胶囊、省名，最后连二维码都被糊了一层。必须把 `shadowColor` 也置成透明才断得干净，
  见 `clearShadow()`。`drawMap` 也自己清一遍，不信任调用方的状态。

  这个坑用浏览器验证抓不到 —— 浏览器是按规范来的，渲染出来干干净净。真机才现原形。
  同类问题还有 `globalAlpha`、`clip`：出图 canvas 是复用节点，`draw()` 开头统一清一次。

  顺带一提，修掉之后地图的外发光会一起消失（那圈光本来就是漏出来的）。
  `LAND_GLOW` 就是它的可控版本，默认开着，只作用于陆地。


- **出图画布不能用离屏 canvas**。`wx.canvasToTempFilePath` 只认页面上的真实节点，
  所以 `travel-map.wxml` 里有一个 1080×1920 的 canvas 用 `position:fixed; left:-10000px`
  挪到屏幕外。不能用 `display:none`，那样不渲染。
- **`canvasToTempFilePath` 的单位**：`width/height` 是逻辑坐标（ctx 已经 scale 过），
  `destWidth/destHeight` 才是输出像素。写反了只会导出左上角四分之一。
- **画布过大安卓会失败**。默认 2 倍即 2160×3840，部分机型直接生成失败，
  代码里 catch 住降到 1 倍重试一次。
- **保存到相册需要隐私协议**。`wx.saveImageToPhotosAlbum` 要求小程序在公众平台后台
  配好《用户隐私保护指引》并勾选「相册（相机胶卷）权限」，否则真机上会直接失败。
  开发者工具里不拦，容易漏。
- **提审是整体重审**。这是已上线小程序新增页面，提交后整个小程序会被重新审一遍。
  另外中国地图的公开展示涉及《地图管理条例》，本页画的是 34 个省级行政区 +
  台湾 + 南海诸岛十段线，画法本身合规，但仍可能被问到。

## 重新生成 provinces.js

数据来自阿里 [DataV.GeoAtlas](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json)，
经 Albers 等积圆锥投影（中央经线 105°E，标准纬线 25°/47°）+ Douglas-Peucker 简化，
570KB GeoJSON 压到 166KB 路径。投影和简化的脚本在网页版项目里（`build/geo.py`），
这边只做一次格式转换：

```bash
python3 - <<'PY'
import json, io
d = json.load(open('<网页版>/src/provinces.json', encoding='utf-8'))
io.open('provinces.js', 'w', encoding='utf-8').write(
    'module.exports = ' + json.dumps(d, ensure_ascii=False, separators=(',', ':')) + '\n')
PY
```

「超过全国 X% 的人」是照抖音那个梗做的**趣味估算**（`poster.PCT` 曲线），不是统计数据。

### 存档 v2

key 是 `travel-map/v2`，结构见 `store.js` 文件头。第一次读到 v1（`travel-map/v1`，id 数组）会迁移一次，
v1 的 key **不删**，回滚到老版本时数据还在。

### 分享编码的顺序不能动

`share.js` 按 `provinces.js` 里 `provinces` 数组的顺序编码，和网页版一致。
重新生成 `provinces.js` 时如果省份顺序变了，已经发出去的链接会解成别的省。

### 分享图样式

`poster.js` 的 `STYLES`。三种都在同一个出图画布上画，`poster.draw` 返回实际用的版式。

| 样式 | 版式 | 内容 |
| --- | --- | --- |
| `glow` 夜光（默认） | 9:16、4:5 | 标题降成小字，主角是一个大数字「N 个省」；城市 · 国土 · 人口一行；旅行者类型做成标签；地图；七大区进度条（集齐的数字换主色） |
| `stamps` 集邮册 | 9:16 | 34 个省按七大区排成 6×6 邮票墙，点亮的是带齿孔、歪 ±6° 的彩色邮票并印首次点亮日期（v1 迁来的没日期就不印）；最后两格放「下一站」 |
| `paper` 明信片 | 9:16 | 和夜光同一套版式，米白纸纹 + 双线边框，点亮是印章红 |

几条约定：

- **「超过全国 X% 的人」不上图**，只留在页面计数板。那个数是编的，而且图上只要一个主角数字。
- **明信片的配色走 `paint.applyPaper()`**，会改 `paint.C` 的 void/ink 和几个省名颜色、关掉光晕和陆地外发光。
  `poster.draw` 在 `finally` 里调 `applyTheme` 复位 —— `paint.C` 是屏幕地图和出图共用的，
  不复位的话出完一张明信片，屏幕上的地图就成米色的了。`applyTheme` 现在会把这些字段全部复位。
- 浅色底上，有引线的小省（北京、上海、港澳、天津）点亮后省名不能是白字，用 `C.labelLead`（印章红）。
- 集邮册和明信片不支持 4:5：选它们时版式自动回到长图，「朋友圈 4:5」按钮变灰，点了提示一句。
- 出图途中切样式或版式不会丢：`render()` 会在当前这张出完后按最新选择再出一张。

### 4:5 图的码

夜光 4:5 的码卡 180px。朋友圈把 1080×1350 的长边压到 1080 左右，码约 144px，比长图压完的 125px 还大一些。

### 重新生成 cities.js

从 DataV 拉每个省的 `{adcode}_full.json`，只取下一级的 `properties.name`，去掉「市」「地区」「林区」，
自治州 / 自治县去掉民族部分（延边朝鲜族自治州 → 延边州）。直辖市、港澳、台湾不下钻。
